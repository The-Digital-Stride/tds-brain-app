Project email threads

An email thread is a long chain of replies on one subject. Often several teammates are on the same one. This plan helps the project keep one tidy copy of the story, with no repeats and nothing saved without a click.

1 · The problem

Two teammates, one thread, one project

2 · Paste the code once

One code keeps later replies on the project

Each project has a short code, like [AST4K7]. Put it in any message of a thread, once. After that, later replies still point at the project. The code only suggests a project. You still decide.

3 · Start from the project

The code is already in the new email

4 · Same thread, two inboxes

A fingerprint tells the app it is one conversation

Every message gets a fingerprint: a short scrambled code that can't be turned back into the email. It is made from who sent the message, the minute it was sent and the subject. Sam and Alex see the same three things, so they get the same fingerprint. That is how the app knows they are looking at one conversation.

5 · Only what's new

Claude asks first, then writes only the new part

Before writing a summary, Claude asks the project which messages it already holds. It summarises only the newer ones. If nothing is new, it writes no draft at all.

6 · The gate

Always your OK

This is the risky step, so it has a gate. Each person approves exactly what is saved from their own inbox. The summary sits under Waiting for your OK until you press Save to project. A code or a thread match never skips this step.

If Sam saves a message first, Alex's waiting draft for that same message is hidden, not deleted. It comes back if Sam's entry is removed.

7 · One row per thread

The Updates tab shows one conversation, not many rows
