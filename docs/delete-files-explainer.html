Deleting library files

Soon you'll be able to delete an image or document from the library. The file isn't erased straight away. It waits in a safe folder for 30 days, and every delete is written in a list the whole team can see.

The action log

Each person has their own list on each Mac, so two people (or one person on two Macs) never write in the same file at the same time. Lines are only ever added, never changed. A line looks like this, shown here in plain words:

15 Nov 2026, 10:42 Ian Hancock deleted clients/acme/reports/old-audit.pdf from TDS Brain App 15 Nov 2026, 14:05 Ian Hancock put back clients/acme/reports/old-audit.pdf from a chat 15 Dec 2026, 09:00 Ben erased clients/acme/brand/old-logo.png 30-day clean-up

Learn: audit log. A running list, only ever added to, of who did what and when. Here it lets the team see who deleted a client's file, and find it again.

The tricky bits, and how the plan handles them

  • A private file could leakFiles kept on one Mac would be shared if they were moved into the holding folder. The tool asks git first and refuses those files. If git can't answer, it refuses anyway.
  • Erasing can't be undoneThe clean-up erases only when everything about the file checks out: its note reads properly, and both of its dates are over 30 days old. It skips the whole run while a save or merge is part-way through.
  • Two people at onceIf two people delete the same file, the first one wins and the second is told it's already gone. If one person deletes a file while another edits it, the edit follows the file into the holding folder, and the tool flags it as "changed after deletion".
  • Big filesDeleted files keep syncing to everyone for up to 30 days, because the holding folder is shared.
