# Brain skills for TDS Cortex

These are Claude Code skills for the Agency Brain, so a team member can install, update and check
TDS Cortex by typing one command in Claude in their brain folder:

| Skill | What it does |
|---|---|
| `/install-brain-app` | Checks the Mac, downloads and builds the app, sets it to start at login, signs in and adds it to the Dock |
| `/update-brain-app` | Shows what's new, warns that a restart closes open chats, then updates, restarts and checks |
| `/doctor-brain-app` | Runs `bin/tds-brain doctor` and explains each problem in plain words |
| `/tdsapp-todo` | Adds, edits, passes on, re-dates, deletes and ticks to-dos, and links library files to them (or unlinks them) in a `## Files` section, the way the Workbench does plus the fixes in `os/tds-brain-app/change-requests.md` marked "Built in the skill". The app runs its script (`tdsapp-todo/scripts/tdsapp-todo.cjs`) for every to-do change except the tick (still the app's own code, for now), so it never writes those changes itself. Open to the whole team (`roles: owner, scout, team`, Ian, 2026-11-25) so a team member can add a feature request to the TDS Cortex Feedback project; `maturity: draft`. v0.6 (projects plan 2026-11-20) adds the `project` action (client, project and stage together), project fields on `add`, `dropProject` on `move` so a private project never reaches the team, and `projects/` files as links. Copy it without `scripts/tdsapp-todo.test.ts`, `test/` and `test-fixtures/`. |
| `/tdsapp-skill-levels` | Sets, clears or bulk-imports the team's level (Quick, Standard or Deep) for a skill, in `.claude/tdsapp-skill-levels.json`, which only its script writes. The app reads that file to choose how hard Claude works when it runs a skill, and runs the script for its Skill levels settings. Doesn't touch any skill's own file. In testing: `roles: owner, scout` and `maturity: draft` until Pete releases it. Copy it without `scripts/tdsapp-skill-levels.test.ts`. |
| `/tdsapp-kits` | Shows, changes and reviews the start-up kits (short lists of connectors and plugins for one kind of work) in `.claude/tdsapp-kits.json`, which only its script writes. In shadow mode the app only notes which kit it would pick for each chat and switches nothing off; `review` shows how the picks would have gone. Also holds `tdsapp-usage.cjs`, which files the app's per-chat events in `z-logs/app-usage/`. Its `SYNC_APP_EVENTS` switch stays off until Pete confirms the Command Centre skips unknown events. In testing: `roles: owner, scout` and `maturity: draft`. Copy it without `scripts/tdsapp-kits.test.ts`. |
| `/tdsapp-files` | Deletes images and documents from the library into `tdsapp-deleted/`, puts them back, lists what's waiting, and erases each one 30 days after it was deleted. Adds uploaded files to a client's `files/` or `images/` folder (or `personal/files/` and `personal/images/`, which never sync), never overwriting. Every delete, put-back and erase, and every client add, goes in a team log in `tdsapp-deleted/log/` (one file per person per Mac). The app runs its script (`tdsapp-files/scripts/tdsapp-files.cjs`) for the library's bin buttons, a daily clear-out and uploads to to-dos, so it never moves, adds or erases these files itself. Client files (deleting and adding) for anyone on the team, templates for the owner only. In testing: `roles: owner, scout` and `maturity: draft` until Pete releases it. v0.3 refuses to delete a project's own files (`project.md`, `retainer.md`, `updates/`, `months/`). Copy it without `scripts/tdsapp-files.test.ts`. |
| `/tdsapp-ads` | The bridge for Ad Manager, the Workbench section's first tool: reads and decides ads-manager proposals, runs a dry run or the live apply, drafts the client email, records the client's yes or a decision, signs off a monthly report, and reads the Ads board and Daily Standup, as the person at this Mac (git user on the roster). Every rule stays in the brain's `ads-manager` scripts (`proposals.cjs`, `monthly.cjs`, `apply.cjs`, `client-draft.cjs`), loaded at run time; the Workbench's board, approvals and standup readers are ported into `scripts/lib/` and its card prompts are in `scripts/cadence-tasks.json`, word for word (sources and sha256 in `SOURCES.md`). The app runs `apply`, `dry-run` and `sign-monthly` detached and never stops them. In testing: `roles: owner, scout` and `maturity: draft` until Pete releases it. Copy it without `scripts/tdsapp-ads.test.ts`, `test-fixtures/` and `SOURCES.md`. |
| `/tdsapp-projects` | Makes projects and changes their cards: starts a project inside a client (or The Digital Stride for internal work, or your personal space), adds a card to an existing project folder, changes its status, lights, Account Owner, team, service, dates, budget hours, stages or brief, and links or unlinks files. It writes only `project.md`, checks the file hasn't changed since it was read, never overwrites, and won't link a personal file to a shared project. Who did it comes from this Mac's git identity. The app runs its script (`tdsapp-projects/scripts/tdsapp-projects.cjs`) for the Projects app. In testing: `roles: owner, scout` and `maturity: draft` until Pete releases it. Copy it without `test/` (and later `brain-rules/`, which is text for Ian to apply by hand). |
| `/todo` | **Deprecated** (renamed `tdsapp-todo` in v0.3). A shim kept for one release so an older app still works: its script just runs `tdsapp-todo.cjs`. Remove it once every installed app is v0.6 or later. |

They're written and reviewed here, next to the code they drive. Copying them into the brain's
`.claude/skills/` is a separate step that needs Ian's approval, because it changes the shared brain
everyone syncs. When a command or path in `bin/tds-brain` changes, update these skills in the same
change and copy them across again.

Everything TDS Cortex adds to the brain is named `tdsapp-…` from 2026-11-13 (the three install,
update and doctor skills came first and keep their names). Every change stays backward compatible
with older brain files, older copies of the app and the brain's other readers.

Brain conventions they follow: `members: false` (the brain-update tool leaves them alone),
`agency: true`, and a `USE WHEN` list in the description.
